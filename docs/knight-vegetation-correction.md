# Knight stair vegetation correction · 2026-11-03

Local, unpublished. ENV-01, ENV-03 and ENV-06 remain level 1. One illustrative conifer whose trunk visibly stood on a Knight approach stair was moved from ENU (-603.521, -186.550) to (-619, -188), with its height adjusted to the existing terrain. This is a practical art correction, not a surveyed tree location or proof of accessibility. [Before](images/knight-landscape-review.png) · [after](images/knight-landscape-after.png). Shrubs still intrude near the stair and need a separate correction.

The original `campus-expanded.glb`, building geometry and roof Blender file were not rewritten. An isolated editable vegetation candidate and a small source-pinned patch were generated from the preserved Blender mesh and pilot tree inputs. In the existing GLB the tree has 204 material/normal-split vertices representing 68 unique positions; matching was verified before any runtime translation. Comparing the original and separately exported candidate vegetation confirmed that only these 204 vertex positions differed across the four material primitives. The runtime applies the patch only if the declared asset hash and all expected positions/counts match, otherwise it fails explicitly rather than applying a partial move. Geometry bounds are recomputed.

`python scripts/refine-pilot-vegetation.py` under Blender 4.5 generates the isolated editable candidate and JSON using the recorded roof blend and pilot input hashes. It intentionally stops when those snapshots change; revalidate the selected tree after a rebuild. The generated pilot input under `artifacts/` may need regeneration in a clean checkout. The small patch and local viewer changes are registered in `viewer-overrides.json` and the new assets in `data/asset-sources/manifest.json`. Updating the combined presentation asset can invalidate the patch and the expansion builder can discard its configuration; inspect and reapply deliberately.

Validated in local Chrome/SwiftShader: scene and ground loaded, no page errors, same camera comparison, 534 building records and 600 tree count retained. Production build and 43 unit tests passed, including an atomic mismatch test. No hardware performance claim.

The paired inferred shrub was subsequently moved by the same offset using a second source-pinned patch. [Tree and shrub after](images/knight-landscape-tree-and-shrub.png). The separate Blender comparison found exactly 68 tree vertices and 63 shrub vertices translated, with unchanged vertex and polygon counts in both meshes. Another shrub at the edge and the actual approach still need review. Browser load, production build and 43 unit tests passed after both patches.

Final local verification after both patches: the full-campus loading and movement browser regression passed. Before the shrub follow-up, all nine campus/interior browser tests passed.
