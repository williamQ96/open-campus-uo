# 路线与验收

以下均为待完成工作；本次初始化仅建立仓库和设计文档。

## M0：确定数据与试验区

- [ ] 划定 Memorial Quad 周边约 300 × 300 米 AOI，并记录实际边界。
- [ ] 核查候选数据集的可用性、采集年份、覆盖、分辨率、坐标及具体使用条件。
- [ ] 建立来源台账，确定水平 CRS、垂直基准和局部原点。
- [ ] 固定 Pipeline 的首个可用版本和本项目配置。

验收：没有来源或使用条件未确认的数据进入正式资产链；不依赖 UO 内部 GIS。

## M1：第一个端到端闭环

- [ ] 通过 Pipeline 生成 DTM 地形与建筑白模。
- [ ] 在 Blender 中保存地形及每栋独立、可替换的建筑资产。
- [ ] 导出 GLB、资产元数据与场景清单，记录 Pipeline 版本和输入来源。
- [ ] 创建 Three.js + Vite 预览，支持查看、选中建筑与检查来源和重建状态。
- [ ] 对照控制点检查位置、高度、比例、法线和轴转换，输出测量报告。

验收：同一配置可以重复生成并在浏览器打开；场景中明确区分估算白模和经过验证的重建资产。没有预先承诺尚未测量的精度或 FPS。

## M2：资产质量与跨引擎验证

- [ ] 选择一栋代表性建筑，以自采照片或补充测量提高几何与材质质量。
- [ ] 修正步道、路缘、台阶及地形连接，制作独立碰撞代理。
- [ ] 在一个额外引擎中验证位置、比例、材质与法线。
- [ ] 加入可复现的几何、导出完整性和来源记录检查。

## M3：规模化与发布评估

- [ ] 逐区域扩展，增加瓦片、LOD、纹理压缩和按需加载。
- [ ] 分别确定代码许可证、原创资产许可证与第三方来源署名要求。
- [ ] 决定是否及如何发布浏览器预览；发布前确认站点和资源的可见性。
- [ ] 根据实测资源大小选择 Pages 或其他资源存储方案。

完整校园、室内、游戏交互与 3DGS 都属于后续扩展，不是初始化交付物。
