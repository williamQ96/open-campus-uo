# Unplaced generic bike-rack candidate — 2026-11-04

A new [standalone three-hoop rack](../assets/props/bike-rack-candidate-2026-11-04.glb) and [neutral view](images/bike-rack-candidate-2026-11-04.png) provide an original, reusable, low-poly prop candidate. The [UO exterior furnishing standards](https://cpfm.uoregon.edu/sites/default/files/_div_32_exterior_improvements_031623.pdf), bike-rack section dated August 2019, describe rail-mounted round hoops in green, with 36-inch height and preferred hoop spacing, 18-inch hoop width and 1⅞-inch pipe. The candidate uses approximately 0.9144 m height and spacing, 0.4572 m hoop width, 0.047625 m tube diameter and 0.0254 × 0.0508 m base rails, with a palette green approximation. Its total rail-inclusive bounding width is about 0.4604 m. Three hoops, low-poly joints, color and rail-end details are illustrative; it is not a model of a specific product or a certified construction drawing. No image, brand or third-party mesh was copied. Original geometry is CC BY 4.0 and code Apache-2.0.

The model is deliberately **not placed in the campus**. UO's [transportation map](https://map.uoregon.edu/transportation-uo) identifies a covered bike-parking region as A27. Its popup coordinate, checked 2026-11-04 and transformed from WGS84 to the project's EPSG:3740 frame using pyproj, corresponds approximately to ENU (-430.15, -29.72) m. This is a map-feature position, not a surveyed installed rack coordinate. The project Tykeson placeholder's northern edge is about 0.82 m from that point and existing inferred shrubs are nearby. A trial rectangle centered at ENU (-427,-27), about 4.17 m from the map point, is roughly 3.14 m from that placeholder footprint and 25.98 m from the nearest modeled navigation-graph edge, but five downward samples of the trial rectangle meet the current modeled **lawn**, not a verified rack pad. This coarse project-only screen is not a field clearance, access or accessibility assessment. The map says the facility is covered; its actual canopy, number, layout and present condition were not reconstructed. Moving an inferred rack or replacing lawn with invented paving would make uncertain placement appear authoritative, so neither was integrated. PROP-01 stays level 1; this candidate does not mean any inventory category is completed.

`apps/web-preview/src/bike-rack-geometry.js` is the editable procedural source and accepts 2–8 hoops; the standalone example contains one combined mesh and three hoops (984 triangles), with no placement, canopy, terrain, collision or navigation data. The GLB reimports with matching source SHA-256, index buffer, positions, normals, color and identity transform. It is not a per-object Blender scene; no new `.blend` snapshot was produced. With local Vite running, reproduce from `apps/web-preview` using `node scripts/export-bike-rack.mjs ../../assets/props/<new-name>.glb`; it refuses existing output and validates source stability and round-trip geometry. Since no rack is loaded by the campus runtime, this asset introduces no current draw calls or in-scene triangles. A future integration must verify the real facility, model relationship, cover, ground, clearance and performance.

Validation passed 128 Node tests, 17 Python preservation/reference tests, four browser checks including standalone export, mobile/navigation and the unchanged draw-call test, production build, formatting, viewer hashes and 129 archived asset hashes. The visual review is isolated; no in-campus preview or site survey has been claimed. Existing build chunk-size warning persists.
