# Dan Carrere fixed-person prototype

This local prototype uses the UO [public directory](https://cas.uoregon.edu/directory/school-of-computer-and-data-sciences/all/dcarrere), accessed 2026-11-04, for name, Associate Teaching Professor / Computer Science role, office context and link. The official portrait was viewed as reference for a brimmed hat and beard and is not stored or distributed. The stylized face and outfit are new procedural geometry and material; skin, clothing colors and the requested taller height are illustrative, not verified measurements. The phrase “you just graduated” is user-requested game dialogue, not a claimed quotation or an audio recording of the person.

The instance uses the existing rigged student base; a source-defined plaid material and bone-attached hat, eyes and beard add to it. A bounded, collision-screened 12 m x/z path near the approximate Deschutes footprint runs at 0.7 m/s with 2 s endpoint pauses; these are authored game behavior, not a record of the person's real location or movements. The normal scene collision screen samples the route and conservative supplemental boxes, not a site accessibility survey. Movement pauses when the model or label is hovered or focused so it can be selected. The lightweight name has no building-style background; a proximity bubble contains the exact user-provided text. Label, model and keyboard interaction open the same native dialog with a concise university profile link; a small gold marker appears on the overview minimap. The NPC is outdoor-only. A building occlusion check hides the label and speech bubble when both torso and head samples are behind scene building meshes; a narrow touch viewport passed label/card interaction. This two-point approximation does not cover vegetation or every partial occlusion; a complete device performance survey remains open.

Local browser checks cover route collision samples, proximity text, name and model hover, click and keyboard and narrow-screen touch card interaction, Escape, official link and the existing longhouse fixed-view draw budget; path unit tests cover both directions, endpoint pause and fixed mode. ## Building occlusion follow-up

Two camera-to-person rays, throttled to at most one check per 120 ms while on screen, test the existing building selection meshes. Fully blocked people hide their name and bubble; a clear head or torso preserves the label. Hidden labels clear hover and return keyboard focus when appropriate; the original card remained open (superseded by the floating-card update below). Off-screen checks stop. The algorithm is approximate, uses building proxies and does not test trees. No person appearance, dialogue or reviewed preview image was changed.

The scene regression uses a camera at (-5, -30) looking at the projected person behind a building and verifies label and bubble hidden, then moves to a clear view and opens the card. Desktop and touch variants passed; unit checks cover full, partial, off-axis and behind-person obstruction. Existing path, selection and 178-draw fixed-view budget and low-frame-rate navigation tests passed. In a four-second local Chrome/SwiftShader clear-view sample, 28 checks totaled 12.6 ms (mean 0.45 ms, maximum 1.9 ms); this is an indicative single-machine sample, not a device-wide frame-time guarantee.
