The layer describes a compilation of contributed datasets, including imagery-based work; it is informational and is not a site survey. The queried bounding box was longitude -123.0805 to -123.063 and latitude 44.039 to 44.052, reprojected by the service to EPSG:3740. A separate count query and extract each returned 664 features on 2026-11-04. The exact reference extract SHA-256 is recorded in the [summary](../data/metadata/oregon-footprint-screen-2026-11-04.json); raw source coordinates are not redistributed here. In this extract 663 records say LCOG with source date unavailable; one says Microsoft OS, best as of 2018. The 664 distinct object IDs contain only 625 distinct ORBLD_ID values, so ORBLD_ID cannot be assumed unique.

The summary screens the 63 named project candidates against source polygons using planar intersections of at least 1 m²: 45 have one hit, 15 have multiple hits and 3 have none. No hit may mean the project candidate is outside the queried area; one hit does not prove an identity. Intersections compare only 2D footprints, with invalid polygons repaired using `buffer(0)`; they do not check height, real mesh collisions, date, or present-day condition. The source item does not state a clear open redistribution license for these contributed data; public availability alone is not treated as authorization to embed source coordinates or derived models.

Reproduce with a separately obtained reference extract in EPSG:3740 and a source count, e.g. `python scripts/screen-reference-footprints.py --geojson <local-extract> --expected-count 664 --output <new-report.json>`. It checks CRS, explicit transfer-limit flags, the expected count and project manifest hash; it refuses to overwrite output. Supplying a count does not by itself establish the correctness of the query or date. Two synthetic tests cover coordinate translation, overlaps, and rejection of wrong CRS/truncated data.
